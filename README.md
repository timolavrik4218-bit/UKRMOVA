# Український клас

Готовий адаптивний сайт для класу української мови та літератури. Він відкривається напряму через `index.html` і має демо-режим без бекенду: дані тестових акаунтів зберігаються лише у `localStorage`.

## Підключення Supabase

1. Створіть проєкт у Supabase і ввімкніть **Authentication → Providers → Email**.
2. Відкрийте **SQL Editor**, вставте вміст [`supabase.sql`](./supabase.sql) і виконайте його.
3. У [`app.js`](./app.js) замініть `SUPABASE_URL` та `SUPABASE_ANON_KEY` на URL і anon key вашого проєкту.
4. Створіть перший акаунт учительки через OTP, а потім у SQL Editor виконайте запит з кінця `supabase.sql`, замінивши номер на її підтверджений номер.

Gmail використовується для OTP. Під час реєстрації учень вводить код реєстрації, який адміністратор створює в адмін-панелі. Код перевіряється на сервері, може мати термін дії та ліміт використань. У базі зберігається лише SHA-256, а в `profiles.identity_key_hash` діє `UNIQUE`-обмеження: один код не можна прив’язати до кількох профілів понад встановлений ліміт. Новий профіль має статус `pending`, і тільки адміністратор після звірки зі шкільним списком натискає «Підтвердити».

RLS-політики не дають звичайним користувачам змінювати профіль, identity-хеш, статус або керувати роботами; це доступно лише `role = 'admin'`. Адміністратор бачить статуси в адмінці, підтверджує особу і видаляє акаунти. Не видавайте один шкільний код двом людям і перевіряйте його за своїм класним списком.

Для локального демо, якщо потрібно побачити адмінку, замініть `DEMO_ADMIN_PHONE` у [`app.js`](./app.js) на свій номер, а потім зареєструйтеся саме з ним. У production цю змінну не використовують — роль задається тільки в Supabase.

## Вхід адміністратора через email

Для адмінського входу сайт використовує Supabase Auth email OTP. Створіть користувача `timo.lavrik4218@gmail.com` у Supabase Auth, а потім призначте його профілю роль адміністратора.

Після створення користувача виконайте в SQL Editor, підставивши UID користувача з Auth Users:

```sql
update public.profiles
set role = 'admin', identity_status = 'verified'
where id = 'AUTH_USER_UUID'
  and email = 'timo.lavrik4218@gmail.com';
```

Після цього кнопка «Адмінка» надішле одноразовий код на Gmail і пропустить лише цей профіль.

## Сесія та вихід

Сесія входу зберігається в браузері (`persistSession: true`), тому після оновлення сторінки користувач залишається авторизованим. Для безпеки після 10 хвилин бездіяльності сайт автоматично завершує Supabase-сесію. Активність визначається натисканнями, рухом миші, прокручуванням і дотиками. Після входу кнопку **Вийти** можна натиснути у верхній частині сайту — це завершує поточну сесію, але не видаляє акаунт.

## Керування кодами реєстрації

Після повторного запуску [`supabase.sql`](./supabase.sql) адміністратор отримує в адмін-панелі розділ **Коди реєстрації**. Там можна:

- створити код із назвою групи;
- обмежити кількість використань від 1 до 100;
- встановити термін дії;
- відкликати активний код;
- переглядати кількість використань і стан кожного коду.

Відкритий код повертається лише під час створення. У базі зберігається тільки SHA-256 хеш. Учень після підтвердження email вводить цей код, а сервер атомарно перевіряє термін дії та ліміт використань. Код більше не приймається після досягнення ліміту.

## Модерація проєктів

Підтверджений учень може натиснути **+ Додати роботу** і надіслати назву, розділ та опис проєкту. Нова робота отримує статус `pending` і не з'являється у відкритій галереї. Адміністратор у блоці **Проєкти учнів** може:

- переглянути автора, розділ, текст і статус;
- дозволити публікацію (`published`);
- відхилити роботу (`rejected`);
- видалити роботу.

Тільки роботи зі статусом `published` показуються іншим відвідувачам. RLS-політики Supabase дозволяють учням створювати лише власні роботи, а змінювати статус або видаляти роботи можуть тільки адміністратори.

Під час створення проєкту учень може додати кілька фото, відео або інших файлів: PDF, документи, презентації, архіви тощо. Файли завантажуються в приватний bucket `work-project-files`, а метадані про них зберігаються в таблиці `public.work_media` разом із роботою.
